Entregável Parcial 2 (EP2) – Modelo Arquitetural do MVP Web
Objetivo da atividade
Nesta etapa do Projeto Integrado III, a equipe deverá elaborar o modelo arquitetural do MVP Web desenvolvido no projeto. O foco da atividade é demonstrar como o sistema está estruturado tecnicamente, evidenciando as decisões arquiteturais adotadas, as tecnologias escolhidas e a organização dos componentes da aplicação.

O objetivo é que a equipe compreenda como a arquitetura de software contribui para a qualidade, escalabilidade, segurança, organização e manutenção de sistemas computacionais.

O que deve ser desenvolvido
A equipe deverá produzir uma documentação arquitetural do MVP Web contendo:

1. Visão Geral da Arquitetura
Apresentar uma descrição geral do sistema, explicando:

Qual problema o sistema resolve;
Qual o objetivo do MVP;
Quem são os usuários do sistema;
Como a aplicação está organizada de forma geral.
2. Modelo Arquitetural do Sistema
A equipe deverá representar a arquitetura do sistema por meio de diagramas e descrições técnicas.

O documento deve apresentar:

a) Estrutura em camadas
Explicar como o sistema foi dividido, por exemplo:

Frontend;
Backend;
Banco de dados;
APIs externas;
Serviços complementares.
b) Componentes da aplicação
Descrever os principais componentes do sistema, como:

Módulo de autenticação;
Cadastro de usuários;
Painel administrativo;
Serviços de integração;
APIs;
Módulos principais do projeto.
Para cada componente, explicar:

Sua função;
Como ele se comunica com os demais;
Sua importância no funcionamento do sistema.
c) Tecnologias utilizadas
Informar e justificar as tecnologias escolhidas:

Exemplos:

Linguagem de programação;
Frameworks;
Banco de dados;
Ferramentas de versionamento;
Serviços em nuvem;
Bibliotecas principais.
A equipe deve explicar:

Por que escolheu essas tecnologias;
Quais vantagens elas oferecem ao projeto.
d) Integrações do sistema
Explicar possíveis integrações realizadas ou planejadas:

Exemplos:

APIs externas;
Serviços de autenticação;
Sistemas de mapas;
Plataformas de armazenamento;
Serviços de envio de e-mail;
Inteligência artificial;
Serviços de monitoramento.
3. Decisões Arquiteturais
A equipe deverá justificar as principais decisões tomadas durante a construção da arquitetura do sistema.

Exemplos:

Escolha da arquitetura MVC;
Uso de APIs REST;
Separação frontend/backend;
Organização em microsserviços ou monolito;
Estratégias de segurança;
Organização do banco de dados.
A justificativa deve demonstrar relação com:

Escalabilidade;
Segurança;
Facilidade de manutenção;
Desempenho;
Organização do código;
Experiência do usuário.
4. Uso de Boas Práticas e Padrões Arquiteturais
Explicar quais boas práticas foram utilizadas no projeto.

Exemplos:

Clean Code;
Separação de responsabilidades;
Reutilização de componentes;
Padronização do código;
Versionamento com Git;
Organização de pastas;
Responsividade;
Segurança de autenticação.
Também devem ser apresentados os padrões arquiteturais adotados, quando aplicável:

MVC;
Cliente-servidor;
REST;
Arquitetura em camadas;
Componentização;
SPA.
[Componente Extensionista]
No arquivo README do repositório GitHub, criar uma seção intitulada:

“O que é Arquitetura de Software?”
Nesta seção, a equipe deverá explicar, com suas próprias palavras:

O que é arquitetura de software;
Qual sua importância no desenvolvimento de sistemas;
Como ela impacta:
escalabilidade;
segurança;
desempenho;
manutenção;
evolução do sistema;
Como a arquitetura influencia diretamente a qualidade de um projeto de software.
⚠️ Não copiar definições prontas da internet. O texto deve demonstrar compreensão da equipe sobre o tema.

Estrutura esperada da entrega
A entrega deverá conter:

Documento arquitetural (PDF ou Markdown);
Diagramas arquiteturais;
README atualizado no GitHub;
Link do repositório GitHub da equipe;
Organização adequada dos arquivos no repositório.
Sugestões de Diagramas
A equipe pode utilizar ferramentas como:

Draw.io;
Lucidchart;
Figma;
Canva;
Mermaid;
StarUML.
Diagramas sugeridos:

Diagrama de arquitetura;
Diagrama de componentes;
Fluxo de comunicação;
Diagrama de camadas;
Fluxo de requisições.
Critérios Avaliativos
Critério	Pontuação
Clareza e consistência do modelo arquitetural	0 – 2,0
Qualidade das justificativas técnicas	0 – 2,0
Uso adequado de padrões arquiteturais e boas práticas	0 – 2,0
Clareza e profundidade das explicações no README	0 – 2,0
Organização, documentação e qualidade do repositório GitHub	0 – 2,0
Informações da Atividade
Elaboração: em equipe;
Intervalo da nota: 0 a 10;
Disciplina integrada: Engenharia de Software;
Tipo de entrega: Relatório + repositório GitHub indicado no repositório + documentação arquitetural. (Total 2 arquivos a serem enviados)
Orientações Finais
A documentação deve ser objetiva, organizada e técnica;
Utilizem linguagem clara e profissional;
Evitem apenas listar tecnologias: expliquem as decisões;
O foco da atividade é demonstrar entendimento arquitetural do sistema;
O repositório deve estar atualizado, organizado e funcional;
Diagramas devem estar legíveis e bem identificados.
